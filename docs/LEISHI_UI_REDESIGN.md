# 晓晓呀 KTV 全端 UI 重构基线

## 目标

以雷石「想唱就唱」商业 KTV 点歌台的页面组织和操作习惯作为参考，保留晓晓呀品牌、现有曲库与播放能力。参考其信息架构和交互模式，不复制雷石商标、专有图标或受版权保护的素材。

## 统一视觉规范

- 主背景：石墨黑与深蓝灰，避免大面积纯黑。
- 主操作色：酒红/正红，用于当前选中、主按钮、播放状态。
- 强调色：香槟金，用于焦点边框、关键数字和少量提示。
- 内容层级：页面底板、功能面板、列表行、焦点/选中态四级清晰区分。
- 交互：电视端必须支持遥控器焦点移动、确认、返回；手机端使用触屏大按钮和固定底部导航。
- 状态：统一加载、空列表、断线重连、操作成功/失败提示。

## 电视端页面清单

- [ ] 首页：顶部快捷控制；左侧播放窗口与快捷入口；中部点歌分类；右侧歌手/推荐专区。
- [ ] 歌名点歌：左侧播放器与拼音键盘；右侧搜索结果、歌曲信息与点播操作。
- [ ] 歌手点歌：地区、性别、组合分类；歌手列表/头像；歌手歌曲列表。
- [ ] 语种、字数、分类：统一二级分类栏与结果列表。
- [ ] 排行榜：热歌、新歌、经典等榜单切换和分页。
- [ ] 已点歌单：当前播放、下一首、置顶、删除、清空等操作。
- [ ] 收藏、常唱、已唱、下载、本地曲库、U 盘、影片。
- [ ] 播放器：播放/暂停、切歌、重唱、原伴唱、音量/音调、全屏控制。
- [ ] 设置、网络、扫码、维护等弹窗与辅助页面。

## 手机扫码点歌端页面清单

- [ ] 点歌大厅：搜索、分类、拼音辅助键盘、热歌推荐。
- [ ] 歌手：地区/性别/组合筛选、歌手歌曲。
- [ ] 排行：榜单分类、歌曲点播。
- [ ] 收藏与已点：同步电视端状态，提供清晰的置顶/删除操作。
- [ ] 遥控：播放控制、原伴唱、音量与均衡器。
- [ ] 连接状态、加载态、空状态、错误提示与断线重连。

## 实施顺序与验收

1. 先完成电视端主框架与首页，再完成电视端所有子页面和遥控焦点。
2. 再统一手机端所有页面的结构、导航、列表与状态。
3. 检查每个按钮仍连接原有业务回调，不以静态 UI 替代功能。
4. 执行 JavaScript 校验、Android QA 构建和单元测试。
5. 生成可安装 APK，按电视遥控和手机触屏两种方式验收。

## 本轮记录

- 调整电视首页三栏比例，缩小左侧播放区占比，让中部点歌入口和右侧歌手专区更平衡。
- 增加电视首页分类卡片留白与歌手卡片间距。
- 手机端扩大分类、歌手筛选、拼音键盘、歌曲操作与分页按钮的触控热区。
- 手机搜索框字号调整为 16px，顶部品牌栏滚动时保持可见，并为底部导航预留安全区。
- 本轮只调整 UI 展示层，不更改点歌 API、播放队列、收藏、音量和均衡器业务逻辑。
- 电视端统一顶部/底部栏的渐变层次、按钮圆角与暖金细边；搜索入口采用酒红主按钮。
- 子页面歌曲列表改为石墨卡片，遥控器选中态统一为酒红渐变与香槟金描边。
- 歌手卡片、歌单卡片统一圆角、背景层次和边框，避免旧版灰色列表行与紫色键盘选中态混用。
- 电视顶部控制按钮和搜索框加高，首页常用入口卡片增加高度，拼音键盘输入区扩大。
- 本轮聚焦视觉系统、排版比例、卡片状态和触控/遥控命中区域，不调整功能定义或业务回调。
- 后续继续按页面完成整体视觉重构，不以单纯换色作为完成标准。
