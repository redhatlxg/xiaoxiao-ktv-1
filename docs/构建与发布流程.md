# 构建与发布流程

## 最高优先级规则：以 v1.6.8 为根基线

- 项目根版本固定为 **v1.6.8 正式版**，根源码基线提交：`bcd42c8a32d7adcf7642041db8b90805b4b0cff8`。
- 根版本只读保护，不在根版本标签、归档或 `stable/1.6.8` 分支上直接开发。
- 所有后续功能、修复和重构均须从 v1.6.8 根基线建立独立分支；后续开发主线也必须保留到根基线的可追溯关系。
- 禁止覆盖、移动或删除 v1.6.8 正式标签、正式 APK、校验文件和私有归档。

## 分支约定

- `stable/1.6.8`：只读根版本分支，永久保留。
- `feature/*`：新功能开发分支，从 v1.6.8 根基线创建。
- `fix/*`：问题修复分支，从 v1.6.8 根基线或经确认的对应开发版本创建，并在记录中注明来源。
- 后续稳定开发分支：仅在明确建立并记录后使用；不得改变 v1.6.8 根版本的只读属性。
- `backup/*`、`archive/*`、`private-backups`：阶段备份和历史归档，不作为日常开发入口。
- 不要为了整理分支而删除历史分支；不得强制推送改写根版本历史。

## 日常开发流程

1. 确认 v1.6.8 根基线和对应源码提交。
2. 从根基线创建独立的 `feature/*` 或 `fix/*` 分支。
3. 修改代码时保持范围清晰，避免无关改动混入同一提交。
4. 提交后运行 Android QA 工作流，检查所有步骤、单元测试和 APK 上传结果。
5. 在目标电视/盒子上安装对应构建，验证遥控器焦点、确认键、触摸点击、点歌、队列、播放、原伴唱切换、手机扫码点歌等相关流程。
6. 实机通过后再合入后续开发主线；没有经过验证的改动不得标记为稳定版本。
7. 更新版本记录，写明根基线、分支、最终提交 SHA、工作流编号、APK、测试结果和已知问题。

## GitHub Actions 构建

仓库工作流文件：`.github/workflows/android-qa.yml`

手动构建：
1. 打开仓库的 Actions 页面。
2. 选择 **Android QA Build**。
3. 点击 **Run workflow**，选择本次开发分支。
4. 等待状态变为成功后，检查所有步骤。
5. 从 Artifacts 或发布页下载 APK；安装前核对提交 SHA 和构建编号。

## QA 与正式版的区别

- QA/debug 包只用于测试，不代表正式签名发布。
- 正式版必须使用受控的正式签名密钥构建。
- 正式版发布前必须确认：版本号和 versionCode 已递增、Release 构建成功、APK 签名有效、安装升级验证通过、目标设备实测通过。
- 正式版使用独立的新 Release 标签；不得复用 v1.6.8 标签或覆盖其资产。
- 每个正式版本单独保留源码提交、APK、SHA-256 文件、构建记录和实测结果。

## 签名安全

项目 Gradle 从环境变量读取签名参数：

- `KTV_STORE_FILE`
- `KTV_STORE_PASSWORD`
- `KTV_KEY_ALIAS`
- `KTV_KEY_PASSWORD`

签名密钥应至少保留两份安全备份。不要把密码写进脚本、README、提交记录或聊天记录。若签名密钥丢失，后续 APK 可能无法作为原应用无缝升级安装。
